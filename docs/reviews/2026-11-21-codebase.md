## Executive Summary

The scaffold is clean, idiomatic and green: `gofmt`, `go vet`, `ruff`, `go test ./...` and `pytest` all pass. The package split is sensible and several invariants are carefully encoded (signature canonicalisation, delta-gate transaction, TTL validation, argv-based command execution).

However, the authorization path is not sound. The two most important safety properties — "broad actions require a human" and "no action outlives 24 hours" — are both bypassable today. `broad` is trusted from untrusted JSON, so a `/8` can be signed and installed with no interrupt; `SignedBackend.Apply` never checks expiry, so an expired signed action replays forever. The reaper also loses all state on restart and stops permanently on the first revoke error. These are not production-readiness gaps in a feature; they defeat the central claim in `docs/05-safety-and-trust-model.md`.

**Most urgent action:** derive broad/CIDR classification inside Go, enforce expiry and mandatory signature verification at the capability layer, and persist pending actions before install.

## Findings

### CRITICAL

- **[operator/cmd/operator/main.go:74-90] `SHR-001` · broad classification trusts the caller** — The operator copies `broad` from untrusted JSON and signs it; `Enforcer`/`SignedBackend` gate only on that value. A request for `10.0.0.0/8` with `broad:false` passes with no interrupt. *Principle: I8/I14 — classification must be derived where capability lives.*
  > Fix: parse the target with `netip.ParsePrefix` in Go, compute `broad` there, and reject a mismatched claimed flag. Never read `broad` from JSON.
- **[enforcerd/verify_signature.go:88-102] `SHR-002` · expired signed actions are accepted** — `SignedBackend.Apply` verifies the signature but never compares `ExpiresAt` with `now`, never calls `ValidateTTL`, and keeps no replay state. A one-minute action signed two hours ago still installs. *Principle: I11 / ADR-0002 — at most 24 hours.*
  > Fix: reject when `now >= ExpiresAt`, validate TTL and clock skew, and test the `-1s / 0 / +1s` boundary plus replay.

### HIGH

- **[enforcerd/enforcer.go:58-101] `SHR-003` · pending actions are not durable** — Reaper state is an in-memory map with no write-before-install and no reload. A crash forgets every installed rule, and `Run` never reaps on startup. *Principle: I12/I13.*
  > Fix: persist `{id,target,kind,expires_at}` before `Apply`, delete after `Revoke`, reload on boot, reap once before the ticker.
- **[enforcerd/enforcer.go:118-136] `SHR-004` · the reaper stops on the first revoke error** — `Run` returns on the first backend failure, permanently ending the loop; `docs/05` says failures are retried next tick. *Principle: failed revocation remains visible and retryable.*
  > Fix: log, retain the action, continue; add a fail-once backend test.
- **[enforcerd/enforcer.go:84-93] `SHR-005` · TTL is anchored to a caller-supplied `CreatedAt`** — `CreatedAt=now+23h` with a 24h TTL yields a 47h lifetime from now. *Principle: I11.*
  > Fix: anchor to `e.now()` or reject timestamps outside a small skew window.
- **[hunterd/cursor/feistel.go:100-111] `SHR-006` · `/32` panics the scanner** — `hostBits=0` reaches `Permute(value, 0, key)`, which panics. Reproduced. *Principle: robustness at a hostile-input boundary; `testing.md` requires `/32`.*
  > Fix: special-case `bits==0` (identity) and return errors instead of panicking; add `/31` and `/32` tests.
- **[orchestrator/policy.py:36-46] `SHR-007` · `/24` skips the human gate** — `broad = prefix_length < 24`, so a 256-address `/24` sets `approved=True` and never interrupts. *Principle: I14 — CIDR blocks always go to `human_gate`.*
  > Fix: make the boundary explicit (`<=` or threshold 25), test `/23 /24 /25`, document it in `policy.yaml`.
- **[orchestrator/score.py:13-23] `SHR-008` · unsigned attributes drive auto-approval** — `known_bad`, `recent_ct` and `shared_fingerprints` come from an unsigned event object; forged values reach 0.99 confidence and an approved mitigation. *Principle: `STATE.md` — attributes are not signed.* *Annotation (ml-add Phase 1): mitigated on the scoring path, since asserted flags add no confidence; producer still unauthenticated, so this stays open.*
  > Fix: accept threat-intel only from an authenticated adapter, not from event attributes.
- **[enforcerd/enforcer.go:71-78] `SHR-009` · signature verification is optional** — `NewEnforcer` accepts any backend and `Enforce` installs unsigned actions; only the optional `SignedBackend` verifies, and nothing constructs it. *Principle: I7/I8.*
  > Fix: require a verified backend in the constructor or verify inside `Enforce`.
- **[operator/cmd/operator/main.go:53-60] `SHR-010` · `keygen` silently overwrites the private key** — `os.WriteFile` truncates an existing file, destroying the trust root. *Principle: operational safety.*
  > Fix: `O_CREATE|O_EXCL`, print the fingerprint, require `-force` to replace.

### MEDIUM

- **[hunterd/probes/http_runner.go:18-35] `SHR-011` · no scope or rate enforcement before dialing** — Both runners dial arbitrary targets; no allowlist, resolved-IP check or shared token bucket exists. *Principle: I1/I2/I6.*
  > Fix: inject a `Scope` and limiter, check every resolved IP, return typed `ERR_OUT_OF_SCOPE`.
- **[orchestrator/policy.py:41-43] `SHR-012` · kind inferred from the first character** — `3example.com` becomes nftables; an httpx URL becomes an RPZ target. *Principle: parse, don't infer.*
  > Fix: `classifyTarget` with `netip` plus hostname validation and target normalisation per source.
- **[orchestrator/score.py:26-31] `SHR-013` · policy constants duplicated** — `0.3`, `0.8` and cycle `2` are hardcoded; `policy.yaml:max_refinement_cycles` is never read. *Principle: DRY / language-idioms.*
  > Fix: load bounds and the cycle cap from `load_policy()`.
- **[orchestrator/cluster.py:9-25] `SHR-014` · the refinement loop cannot change anything** — The cluster hash and indicators are identical on the second pass and only the current event id is recorded. *Principle: KISS.*
  > Fix: enrich from stored history or remove the cycle.
- **[orchestrator/policy.py:50-66] `SHR-015` · `approve_policy` mutates state in place** — It edits `state["policy"]` before returning. *Principle: LangGraph channel semantics.*
  > Fix: copy the dict and return the replacement.
- **[hunterd/probes/probe.go:24-36] `SHR-016` · fingerprint is not stable** — `observed_at` is inside the hashed material, so identical content produces a new digest each run; the marshal error is discarded. *Principle: contract identity.*
  > Fix: exclude timestamps from identity material and propagate the marshal error.
- **[hunterd/probes/http_runner.go:23-57] `SHR-017` · unsynchronised callback result** — `OnResult` writes `result` while `Probe` reads it; `copy` also shadows a builtin. *Principle: concurrency safety.*
  > Fix: use a buffered channel or mutex; add a race test.
- **[hunterd/cmd/hunterd/main.go:141-157] `SHR-018` · ingestion does not verify fingerprint or freshness** — Any 64-hex value is accepted and old timestamps pass. *Principle: data integrity.*
  > Fix: recompute or attest the digest, and bound age.
- **[hunterd/store/badger_store.go:40-62] `SHR-019` · missing checkpoint is indistinguishable from cursor 0** — `LoadCursor` returns `(0, nil)` and a lost checkpoint silently rescans. *Principle: I16.*
  > Fix: return a found flag or typed `ErrNotFound`.
- **[deploy/compose.yaml:39-45] `SHR-020` · privileged lab target uses host networking + NET_ADMIN** — Profile-gated, but grants host firewall/network namespace access. *Principle: least privilege.*
  > Fix: dedicated namespace, drop other capabilities, read-only, documented opt-in.
- **[.github/workflows/ci.yml:19-28] `SHR-021` · CI actions are tag-pinned and unscanned** — No SHA pinning, `govulncheck`, `gosec` or lockfile audit for a security binary. *Principle: supply-chain security.*

- **[.agents/testing.md:13-17] `SHR-022` · required invariant tests are missing** — No `/32`, restart/reaper, expiry-replay or `SignedBackend` tests; `operator/cmd` coverage is 0%, `hunterd/cmd` 39%. *Principle: verification contract.*

- **[docs/05-safety-and-trust-model.md:7-11] `SHR-023` · the trust document overclaims** — It asserts caller-independent signatures and independent broad rejection, contradicted by `SHR-001`, `SHR-002` and `SHR-009`. *Principle: documentation accuracy.*
  > Fix: make the code match, or record the residual gaps against these ids.
- **[enforcerd/rpz/backend.go:34-51] `SHR-024` · permissive DNS validation and TTL-gated revoke** — Accepts `..` and over-long labels; `Revoke` needs `TTL > 0`, so a reconstructed action may be unremovable. *Principle: fail-closed validation; revocation never blocked.*
  > Fix: strict label validation and TTL-independent revoke.

## Top 5 Recommendations

1. **Re-derive authorization data in Go.** Compute `broad` and the target type from the parsed target, not from JSON; sign and enforce the computed values (`SHR-001`, `SHR-007`, `SHR-012`).
2. **Make expiry and signature checks mandatory at `Apply`.** Verify signature, TTL, `CreatedAt` skew and `ExpiresAt` inside the enforcement boundary so the standard path cannot skip them (`SHR-002`, `SHR-005`, `SHR-009`).
3. **Persist and retry the reaper.** Write pending actions before install, reload on startup, reap once on boot, and never exit the loop on a revoke error (`SHR-003`, `SHR-004`).
4. **Make the required invariant tests real.** Add `/31`/`/32`, expiry replay, broad-flag, crash/restart and `SignedBackend` tests; fail CI below a coverage floor for `enforcerd` and the CLIs (`SHR-006`, `SHR-022`).
5. **Remove unsigned inputs from the decision path.** Authenticate threat-intel signals, normalize `DeltaEvent.target` per source, and align `docs/05` with what is actually enforced (`SHR-008`, `SHR-023`).
